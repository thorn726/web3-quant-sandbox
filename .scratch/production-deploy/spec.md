# 规格：生产化部署（自用单服务器）

Status: ready-for-agent

## Problem Statement

项目目前只能在开发机上手动启动：没有开机自启、没有一键部署、快照数据靠手动刷新、断网时服务可能报错。作为唯一用户，我无法把沙盒当作一台服务器上长期运行的研究工具来依赖 —— 重启会丢服务，数据会陈旧，任何故障都需要人工登录救援。

## Solution

一组 make 目标 + systemd 配置，实现：一条命令从零部署；服务器重启后服务自动恢复；快照数据定时自动刷新且断网时静默降级到旧快照；LLM 功能通过服务器本地 `.env` 配置 API key。服务以 HTTP 直连（无域名）+ 防火墙白名单方式供本人访问。永不接实盘交易的红线保持不变。

## User Stories

1. 作为唯一用户，我想在全新服务器上用一条命令完成部署（拉代码 → venv → 依赖 → 前端构建 → 服务启动），所以我不用记部署步骤。
2. 作为唯一用户，我想让服务器重启后服务自动恢复，所以不用每次登录手动拉起。
3. 作为唯一用户，我想让快照数据每天定时自动刷新，所以打开仪表盘看到的是近期数据。
4. 作为唯一用户，我想在服务器断网或数据源不可达时服务继续用旧快照正常运行（不报错、不崩），所以研究不中断。
5. 作为唯一用户，我想通过防火墙白名单只允许自己的 IP 访问服务，所以机器暴露面最小。
6. 作为唯一用户，我想把 LLM API key 配置在服务器本地 `.env` 中（不进 git），所以策略实验室的 AI 功能在生产可用且密钥安全。
7. 作为唯一用户，我想在服务器上运行 `make verify` 一键自检（构建 + 测试 + 边界检查），所以任何部署后都能确认系统健康。
8. 作为唯一用户，我想有一条查看服务状态和日志的命令，所以出问题能快速定位。
9. 作为唯一用户，我想让服务崩溃时 systemd 自动重启它，所以瞬时故障不造成停机。
10. 作为唯一用户，我想在 README 里看到完整的生产部署说明（前置条件、命令序列、防火墙配置、密钥配置），所以换一台服务器也能照着重来。
11. 作为唯一用户，我想保持"不进入实盘执行"的产品边界在生产环境原样生效，所以这个工具始终只输出研究信号。

## Implementation Decisions

- 进程管理用 **systemd 直跑** `.venv/bin/python app.py`（用户已决策，不用 Docker）：unit 文件含 `Restart=on-failure`、`WantedBy=multi-user.target`。
- 部署入口收敛为 **make 目标**（唯一接缝）：目标序列覆盖 venv 创建、依赖安装、前端构建、systemd unit 安装、服务启停与状态查看。现有 `setup` / `verify` 目标复用，不另起炉灶。
- 快照刷新用 **systemd timer**（或 cron，二选一以 systemd timer 为准）定时执行现有 fixtures 构建脚本；刷新失败不影响正在运行的服务。
- 断网降级：数据刷新失败时保留旧快照文件，`/api/dashboard/*` 继续以旧快照响应；若需要在 Python 侧改动，改动收敛在 dashboard fixture 模块的外部行为内。
- 数据策略为**快照兜底 + 可选实时源**：实时源作为增强开关（配置驱动，默认关），本次部署不强依赖任何实时源。
- 安全模型：无域名、HTTP 直连，靠防火墙（ufw/iptables 或云安全组）白名单放行用户 IP 到服务端口；README 记录配置方法。
- LLM 配置沿用现有 `.env` 机制；`.env*` 已在 git 忽略与沙箱保护范围内，密钥只存服务器。
- 实盘边界：不新增任何下单能力；verify.py 中的边界文案校验保持原样并通过。

## Testing Decisions

- **只测外部行为**：部署层的验收是"新机器上按 README 的命令序列走通 + 服务响应 + `make verify` 全绿"，不测 make 目标的内部实现。
- 应用层已有 226 个测试与 verify.py 产物/边界检查作为回归网，不重复覆盖。
- 唯一新增的 pytest：快照刷新的降级行为（数据源不可达 → 旧快照保留、API 正常响应），写在现有 tests/ 风格下，测试对象是 dashboard fixture 模块的外部行为。

## Out of Scope

- 域名、HTTPS、反向代理（用户无域名；未来有域名时另行立项）。
- 多用户/认证体系（自用）。
- Docker/容器化。
- 实盘交易接入（永久红线）。
- 实时数据源的具体选型与接入（本次只留配置开关位）。
- 私有课件 docs/v2 的部署。

## Further Notes

- 服务器信息（IP、OS、是否可达交易所 API）由用户在部署时提供；部署脚本不做硬编码。
- `make verify` 在服务器上执行时需要网络（npm 安装依赖）；离线重部署场景在 README 中说明。
